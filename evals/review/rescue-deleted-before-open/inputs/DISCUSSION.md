## Agent Brief

**Category:** enhancement

**Summary:** An implement run that stops (time limit, cancel, failure) after the agent committed loses those commits, because `implement` is the one code-writing workflow with no rescue. Give it the rescue and resume `fix` and `implement-prd` have (#303): save the stopped run's commits on a side branch, resume from them on the retry, and have the agent commit as soon as its work first passes verify.

**Re-verified at `main` 16939c0 (2026-10-31); still applies, narrowed.** This replaces the brief in the issue body and the shape it described (a salvage step in `implement.yml`, pushing `BRANCH` itself). Changed from it:
- The work is package commands now, so it lands in the commands and the service worker as well as the reusable. Both orchestrators must do it.
- The rescue goes to a **side branch**, as `fix` and `implement-prd` do, using the shared rescue code. The branch the publish step pushes is then never an unverified one, and the gate's lease on that branch is untouched. This departs from the original "push `BRANCH`"; the maintainer should confirm (see the note at the end).
- Kept: the commit-early prompt line, and the out-of-scope list.

**Current behavior:**
- `implement:bundle` runs only where the runner succeeded (`if: success()` on Actions, `going()` in the service worker) and refuses a run with no commits. A run that times out hands over nothing, so the agent's commits vanish with the checkout.
- `implement:prepare` cuts the branch fresh at the base. A retry never sees earlier commits. `implement:publish` leases its push on the gate's tip, so a retry replaces whatever an earlier run pushed.
- `implement:conclude` has no rescue and its failure comment names no branch.
- The prompt has the agent commit once, at the end (#257: one commit, 3 minutes before the limit, after 27 minutes of uncommitted work).

**Desired behavior:**
- A stopped run that the gate claimed hands over its commits, and the conclude step saves them under a lease on `agent/rescue/issue-<n>`, keyed to the issue number so a retitled issue still resumes. No pull request, no review request, no label changes beyond the failure path it already has.
- The bundle step runs however the agent ended, and a run with no commits ahead of the base hands over nothing. It gets a time limit of its own on the service, as `fix:bundle` does, since the agent's limit has already fired.
- The failure comment names the rescue branch and says re-adding `agent:implement` resumes from it; when the loop's token was not minted it says the commits were not saved.
- On a retry, prepare fetches the rescue; an unreadable answer stops the run instead of starting over. The runner resumes from it when it builds on the base the retry starts from, and tells the agent the commits are unverified. One built on a different base is set aside, with a note.
- A run that publishes deletes the rescue; a retry that stops again rescues again, leased on the earlier rescue it started from.
- One line in the prompt: commit as soon as the work first passes the verify command `CLAUDE.md` names, and make later changes as further commits. Prompts name no domain and never the gate command; a test enforces this.

**Acceptance criteria:**
- [ ] A run that reaches its time limit, is cancelled, or fails after the agent committed leaves those commits on the issue's rescue branch, with no pull request and no review requested, on both orchestrators.
- [ ] A stopped run with no commits ahead of the base saves nothing.
- [ ] The failure comment names the rescue branch and says re-adding `agent:implement` resumes from it, or says the commits were not saved and why.
- [ ] A retry whose rescue builds on its own base starts from the rescued commits and is told they are unverified; its push does not overwrite anything someone else pushed.
- [ ] A rescue built on a different base is not built on, and the run says it started fresh.
- [ ] A retitled issue resumes from its rescue.
- [ ] A retry that publishes deletes the rescue; one that stops again rescues again without losing the earlier commits.
- [ ] An unreadable answer about whether a rescue exists stops the run with a sentence a person can act on.
- [ ] The prompt carries the commit-early instruction, and the prompt tests still pass.
- [ ] A run that finishes behaves as today.
